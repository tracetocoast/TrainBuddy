### 追加记录接口

`POST /api/v1/body-measurements`，请求 `{ date: "2026-10-20", time: "09:30", values: { waist: 80.5 } }`，携带 `Idempotency-Key`。

每次创建独立 ID，保存上海时区测量时间 `measuredAt` 和服务端保存时间 `createdAt`。同一天、同一个指标、甚至同一分钟都可以记录多次；不同测量不会覆盖。相同保存意图的重试与并发请求只存一条，防止网络重试造成重复。

新页面已全部使用 POST，旧的按日 PUT 仅保留给旧版接口兼容。新记录保存在 `bodyMeasurementEntries`；GET 合并原有 `bodyMeasurements` 与新增记录。原有数据仅有日期时显示“时间未记录”，不伪造测量时间。已有历史中曾被旧版覆盖的值无法恢复，不声称找回不存在的历史。

趋势点按实际时间排列，每条记录有独立 ID；同日多次测量保留所有点。请求只包含本次测量项目，不复制其他项目的旧值作为新测量。

验证：64 项测试通过，包括同日记录、同分钟/并发幂等、重启持久化、旧数据兼容、时间校验、左右指标和斤公斤换算；25 个 WXML 与 27 个 WXSS 文件通过官方编译器。真实照片和苹果健康接入不在此功能范围内。

## 交互修订：分层查看与单项录入

根据用户反馈，废弃将趋势、11 项指标与全部录入框直接堆在成长页的方案。当前结构为：

1. 成长页：保留本周训练节奏，身体数据仅保留一张入口卡，不再请求或展开身体档案。
2. `pages/body-data`：常用体重、体脂率、腰围的简洁列表；其他指标默认收起，用户主动展开。
3. `pages/body-metric`：单项指标趋势、30/90 天及全部范围、该指标的日期明细。
4. `pages/body-record`：独立记录页，一次填写一个指标。切换项目或日期前，对未保存内容提示确认。更新仅提交选中的指标，保留同一天的其他测量值。

原接口、数据与权限保持不变，已有记录无需迁移。以下指标与存储说明仍适用，原有内嵌布局描述由本节替代。

新增两项页面行为测试，验证单项保存使用原修订号、不提交其他字段，以及取消切换/版本冲突时保留输入。全部 61 项测试通过，24 个模板与 26 个样式文件编译通过。

## 身体档案

成长页保留本周训练节奏，在其下增加身体档案：

- 体重、体脂率、肌肉量、身高。
- 肩围、胸围、腰围、臀围、上臂围、大腿围、小腿围。
- 指标均为选填；同一天只有一条记录，再次保存更新对应日期。支持补录历史，不支持未来日期。
- 30 天、90 天、全部历史；各指标独立趋势，不用其他指标填补缺失值。
- 时间轴按实际日期间距绘制；最近数值、测量日期、区间首末变化、最高/最低值与最近五次测量。
- 指标卡片展示各自最近一次测量日期，避免把不同日期的数据混称为当天体测。
- 单次记录只显示一个点，两次后才计算变化。体脂率变化单位为百分点。变化不标记为自动“好/坏”，不从围度推断体脂，不计算健康诊断分数。
- 围度以 cm、重量以 kg、体脂率以 % 手工记录；单侧围度需保持同侧。肩围为围绕肩部一周，并非肩宽。

参考训记在官方商店说明中的“身体数据”和基于记录生成图表的交互方向，未复用其品牌、代码或资源：https://apps.apple.com/cn/app/id1464915553

## 接口与存储

`GET /api/v1/body-measurements`：获取本人的日期升序记录。可选 `from`、`to`，格式 YYYY-MM-DD。

`PUT /api/v1/body-measurements/:date`：`{ values, base_revision }`。

```json
{
  "values": { "weight": 70.2, "waist": 82, "bodyFat": 20.1 },
  "base_revision": 0
}
```

新增日期修订号为 0；更新需使用该日最新 revision。旧修订返回 409，前端保留填写内容并提供重新载入入口。未提交字段保留旧值，显式 null 清空对应指标，至少保留一项。数字最多保留两位小数；服务端在修改状态前完成白名单、类型、范围与日期校验。

记录存储在现有 JSON 数据文件的 `bodyMeasurements` 字段，兼容旧数据；重启后仍可读取。现有项目使用本地文件后端，这不等于生产云存储或多设备同步已上线。

记录由服务端登录身份归属，仅本人可读写。教练绑定和原日记 `body_state` 授权不会自动开放该档案。此轮不增加教练共享、整条删除、目标值、体脂秤或 Apple Health 自动同步；需要后续单独设计。
