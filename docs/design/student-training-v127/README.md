# TrainBuddy V1.27 — 学员端训练模块 28 场景原型规范

> 设计基线：main `0a1a941c40dede9a2817d98fded00ffbc9bef876`（V1.26，2026-11-12）。
> 这是一套 **待实施的产品设计稿**，不是验收截图。逐场景高分辨率 PNG、Word、PDF 已随 ChatGPT 交付给用户；将 ZIP 上传至 Codex 后按编号逐一对照。**不要把模拟数字写死到真实小程序。**

## 产品方向

- 学员三导航维持 **首页 / 训练 / 进展**，教练端工作台/学员/日程不动。
- 采用暖白底色与森林绿（#F8FAF6 / #176D49 / #25352C）；列表与分割线优先，减少同权重大卡片、按钮、动效。
- 核心路径：继续/新建 → 常用动作/筛选/多选 → 动作折叠列表 → 原位组数据 → 完成/休息 → 结束 → 只读报告 → 日历回顾。
- 训练内容、教练发布报告、身体与饮食记录来自独立合法数据域，不能为了视效假造统计。

## 用户状态与数据契约

### 启动与会话
1. 有未完成训练则默认 **继续训练**；新建时保留旧草稿，不能覆盖。多个草稿展示可选择列表。
2. 选择动作时保存已选项；一次确认加入多个。新增未知重量使用 `null`，不要默认 0。
3. 已发布计划优先其目标组；自由训练历史动作使用最近一次有效完成会话；无历史采用动作库有依据的默认参数。

### 训练组原位编辑
1. 展开动作只变化当前动作 ID，不改变会话状态；每行由组类型、重量、次数、完成组成。
2. 热身类型的暖红提示与完成态浅绿提示分别表达，点击组别可直接切换。新增组继承最近主动选择类型，但原有组不被暗改。
3. 输入用原生数字键盘，支持小数与输入中间态，失焦后串行保存，旧响应不得覆盖新值。显示「本地暂存 / 同步中 / 已保存 / 未同步」。
4. 完成后仅当服务端确认才改绿色；已完成组需撤销后再改，新增组默认待完成。结束训练时明确剩余组的处理方式。
5. 根据动作 loadBasis 展示「杠铃杆+两侧片总重 / 单只哑铃重量 / 机器配重 / 自重及额外负重」等说明。不混算训练容量。
6. 休息计时为底部轻量浮层，可暂停/跳过；切后台使用截止时间戳，不依赖 setInterval 的累加准确性；减少动效不等于禁止计时。

### 报告与历史
1. 学员报告只读：日期、真实动作数/完成组、逐组参数、训练部位映射、公开教练反馈；不向学员下发私人备注。
2. 日历默认训练模式，身体与饮食是分类切换。人工标题 > 教练确认标题 > 肌群映射标题 > 中性标题。同一天多条记录分开展示。
3. 未记录数据用「未记录」；无权限、网络失败、无数据是三个不同空状态。
4. 训练统计、容量、时长和肌群图没有可靠数据源时隐藏，不得推断成真实值。

## 改造优先级

**P0 上线安全**：训练组语义、保存一致性、当前登录账号隔离、未完成会话恢复、已完成只读、历史授权和异常恢复。

**P1 高频交互**：动作列表与多选、历史预填、行内热身切换、计重说明、组间休息、训练首页层级。

**P2 增强**：训练/身体/饮食日历精修、动作统计报表、训练部位图、深浅主题与分享图。P2 不得阻塞上线。
