# 训练计划编辑与动作库加入

更新日期：2026-10-19。对应功能设计文档 7.1、7.4、8.1、8.2、13.1。

## 当前完成的流程

动作详情「加入个人计划草稿」调用后端，将当前已审核动作加入私人计划，不再创建无关的默认下肢计划。新增组的重量、次数留空，用户确认后发布。

编辑页支持动作增删和排序、组增删、逐组重量与次数、重量口径、计划日期、目标和调整说明。输入阶段保留在本地，保存时统一提交全部内容，避免逐输入请求覆盖其他修改。

已发布版可显式创建下一版本草稿。保存草稿不改变已发布版；发布后，已开始训练继续使用原计划快照。

## 接口

- `POST /api/v1/plans/personal/exercises`：输入 `exercise_id`，携带 `Idempotency-Key`。实际学员由登录身份确定。仅接受已审核动作；重试同一请求不重复加入。返回计划，含 `can_edit`。
- `GET /api/v1/plans`、`GET /api/v1/plans/:id`：作者可查看自己的草稿；教练作者需要有效服务关系；学员只能查看教练已发布版，返回 `latest_draft: null`；无关账户不可读。
- `PATCH /api/v1/plans/:id/draft`：作者编辑；已有草稿必须提供 `version` 和 `base_revision`，可提交 `title`、`goal`、`plannedDate`、`reason`、完整 `exercises` 数组。已发布计划创建新草稿时传当前发布 `version`。
- `POST /api/v1/plans/:id/publish`：必须提供当前 `version`、`base_revision` 和 `review_confirmation: true`，幂等键包含计划、版本和修订号。

`version` 表示计划版本；`latest_draft.revision` 表示同一草稿编辑修订号，保存后增加。旧页面修改、发布返回 409 `REVISION_CONFLICT`，前端保留本地修改，不自动覆盖。

重量支持 0–500 kg（小数）；次数为 1–200 的整数；每动作 1–30 组；最多 50 个动作。草稿允许空重量、空次数，发布时须填写必填值并确认口径。自重允许空重量。日期验证真实年月日，发布日期不能早于业务当天。校验在变更共享内存前完成。

## 权限

只有作者能修改或发布；绑定教练不能修改学员自己创建的个人计划。教练计划草稿不向学员公开；学员可读已发布版，但不能编辑。解绑后原教练失去继续修改和读取健康计划的权限。
