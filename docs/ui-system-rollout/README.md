# TrainBuddy 全局 UI 落地

分支：`feat/interaction-system-v2`，基于交互提交 `8c00f521c65452307c969e466c52cc29e4cf186c`。本轮获得用户“整体 UI 重设计全面落地”的授权后实施，已修改实际原生小程序，不是仅更新 HTML 设计稿。

## 设计与实现

采用 Precision Daylight：浅灰底、白色内容区、石墨训练主卡、精准蓝操作色，少量青柠用于训练完成入口。品牌为原创几何 T 与哑铃结合的标记；黑白轮廓在小尺寸下可识别，替换所有品牌组件和旧 SVG。导航有统一线性图标和独立选中状态。

`miniprogram/styles/tokens.wxss` 定义公共颜色、圆角与动效参数，`styles/base.wxss` 定义全局标题、数字、表单、列表、按钮和状态反馈；`app.wxss` 统一引入。26 个路由均使用新底色、文字和公共控件；各页面原有绿色硬编码样式迁移为共享语义值。未引入 UI 框架、字体包或动效运行库。

## 数据与权限边界

- 首页展示读取真实 API 返回，不填假预约/训练/绩效。正在加载、没有计划、未绑定及请求失败分别呈现。
- 首页响应检查账号、角色和刷新序号，迟到响应不覆盖新身份页面。原服务端角色授予逻辑继续使用；新增角色从 `/me` 同步。
- 教练页的数据统计只来自自己管理的课程和绑定学员；不推断未授权学员的执行情况。
- 修改集中在 `miniprogram/`、前端测试与文档，未改后端业务、数据库和部署。原有 `project.config.json` 和 `config.generated.js` 本地改动未纳入提交。

## 验证

1. 微信官方编译器：33 个 WXML、38 个 WXSS 编译退出码均为 0；JSON/JavaScript 语法通过。
2. 全量回归 135/135 通过，含新增 10 项：双角色首页数据、未来计划排除、过期预约排除、加载失败、账号迟到响应、26 页自定义组件/事件注册、日记锚点、录入切换保留、教练同步最新 revision。
3. 已实际观察微信开发者工具中的新版学员首页和品牌，发现并修复原生按钮默认宽度造成的头像及 CTA 拉伸。
4. 官方自动化启动仍停在空白窗口，SDK 无法连接；不能据此宣布 26 页逐项真机验收完成。iOS/Android 真机手势、键盘和帧率仍未验证。

原始全量日志与官方编译结果在本目录 `evidence/`；本机真实截图及前后对照在 `output/trainbuddy-ui-rollout`，同时整理到用户桌面测试文件夹。截图只代表当时页面实际渲染，不替代业务联调或性能测试。

## 验收顺序

学员：登录 → 首页继续训练/选计划 → 逐组记录 → 结束 → 成长 → 教练协作/预约 → 身体数据 → 训练补给 → AI 工具。

教练：切换已授予角色 → 今日安排 → 学员档案与计划 → 编排/发布 → 课后语音/文字 → 逐组核对 → 同步 → 后续计划。

继续按 `docs/interaction-system-v2/verification.md` 的双平台用例复核。大模型未配置时，实际生图和营养准确性不能借 UI 测试通过来证明。
