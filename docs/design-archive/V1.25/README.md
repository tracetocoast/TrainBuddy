## 1. 当前信息层级与根因

- **无活跃训练时**：顶部是减少动效开关、品牌区、英文副标题和「训练」。主按钮「新建训练」之后，组件把最近报告与整个训练历史一起展示，最后才是待练计划。历史条目多时，待练计划被推到很下方。计划卡各自都有实心主按钮，和新建训练争夺注意力。
- **有活跃训练时**：`workout.reload()` 优先读取 `in_progress/draft`；正常进入会直接 `applySession`，不会看到明确的「继续训练」入口。历史返回 `?history=1` 或训练内返回会设置 `_browsePlans`，此时虽已查到活跃会话，首页仍展示「新建训练」。应将「存在活跃会话」与「当前显示执行器」分开，不能以是否已进入执行器决定主按钮。
- **组参数**：main 上重量、次数和组类型进入同一个 `set-editor`。工作区已将数字改为行内原生 `input`，组类型仍打开底部面板；输入只写 `pending`，完成、组增删前或结束训练才提交，没有 `blur/confirm` 自动保存。已完成组必须明确撤销完成后改数值，这条规则应保留。
- **组数**：当前「新增一组」和每行减号复用 `onChangeGroup`，成功后使用返回会话，服务端沿用组数上下限。删除没有确认；增删前会冲刷所有 `pending`，一处无效输入会阻止组操作。`applySession` 也可能重算锁定动作、选中组和折叠状态，不能简单将每个保存响应直接重建整个页。
- **状态反馈**：main 完成本组后有固定底部重复按钮、休息遮罩、动作完成全屏反馈；工作区已用右侧完成按钮、浅绿整行和非阻塞行下提示取代这些区域。后续保留这部分成果，仅整理余留样式和状态。
- **报告颜色**：`report-history/index.wxss` 在 `.history` 定义深色，但 `.latest`/`.row` 为原生 button，无显式主文字色；组件内部又写死浅色卡和固定灰绿，不能依赖页面根层、组件隔离或设备默认按钮色获得一致结果。`training-report/index.wxss` 写死浅色，WXML 根层也没接 `skinClass/pageBg`，可与全局暗色导航形成两套色彩。以上为样式证据；当前未取得真机颜色截图，不猜设备最终渲染。

下表从训练首页起算；动作库中的搜索、分类和滚动不计入最低点击数。一次页面进入/退出只算一次路由变更，页面内状态变化不算跳页。

|改四组重量和次数|main 数值逐个打开/收起底部面板，8 个字段约 16 次触控；工作区 8 次字段聚焦，已无数值面板|0|保留 8 次字段聚焦；键盘确认/失焦触发行保存，完成不要求先收起另一层 UI|

## 4. 原位编辑与保存队列兼容方案（阶段二核心）

当前 `onSetField` 会复制整个 session、更新 `pending` 和本地草稿；`saveSet` 读取当前行后 PATCH，成功清除整行 `pending[setId]` 并应用服务端完整会话。`_writeBusy` 会挡住并发输入；直接放开就会让已发请求清掉等待期间新输入，或旧完整快照重绘其他行。组 PATCH 当前没有 revision 比较参数，不能声称前端方案解决跨设备覆盖。

1. **本地值**：`bindinput` 更新当前行的原始字符串，按账号、角色、会话、组与字段保存未同步草稿。保留空值和 `7.` 等输入中间态，0 与缺失不混同。选择动作、列表滚动和输入焦点使用稳定组 ID；避免每次敲键重新选组或重建动作列表。
2. **提交触发**：`bindblur` 与 `bindconfirm` 共享调度，按组合并字段；相同版本只排一次。仍走既有 `updateActualSet` 和数值边界；非法数字留在当前单元格并标错，不能静默回退至默认值。保存数字只改数值，不能顺带改变组状态。
3. **串行与旧响应**：单 session 一条写队列，每次记录发出时的字段编辑版本及不可变 payload。收到成功响应时按字段版本清理本次确已保存项；较新编辑和其他组草稿重新覆盖服务端快照。只应用同账号/角色/session 的响应，按现有 revision 拒绝落后快照；不用请求回包时间猜顺序。数字可继续输入，涉及结构变更、完成或结束的操作加入同一序列，避免旧保护与新队列双写。
4. **失败与恢复**：保留本地数值并标记「未同步 · 重试」，支持重试对应组。重试未发的最新数字，不能用旧快照覆盖新编辑。权限变化或会话已结束时保留未确认草稿但禁止继续写入。切动作不等于切账号或切会话；不阻止当前页查历史。恢复时先加载真实会话，只合并属于它且仍存在的组草稿。
5. **状态/结构操作**：完成按钮使用当前组最新合法数值加原有 `state`，等待确认后才变绿；重复点同一组不重复提交。新增组在当前动作尾部插入，以 API 成功结果为准。删除放行内「更多」，先确认组号及影响，成功后才移除这一组草稿；保留最后一组保护。组类型走原 PATCH，只改 `setType`，用行内短选项而非全页面板。结束训练等待所有有效保存并使用最新服务端 revision，失败不自动 finalize。跨设备冲突策略仍服从既有服务端接口。
