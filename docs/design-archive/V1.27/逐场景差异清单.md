## 首批只修 P0

| 顺序 | 确认的问题 | 改法和验收 |
|---|---|---|
| P0-1 保存 | `saveSet` 以整行数值生成 PATCH；服务器没有编辑版本条件。单页串行保护存在，但无法防第二设备或迟到的旧写覆盖其他字段。成功、失败和输入也未分为独立的状态。 | 按账号、角色、会话、组及字段隔离本机输入，只发送变更字段；为学员写操作引入兼容的版本条件，冲突保留本机草稿并提示重新载入。失焦、完成、切动作、离页、结束使用统一的写入边界。验收：四组连续输入、同一字段二次修改、跨设备不同字段并发、断网恢复与迟到响应。 |
| P0-2 重量与状态 | `updateActualSet` 只在 manual 标记完成时要求数字；没有完整范围、会话可编辑态和已完成组的服务端限制。自由训练历史先选合法数字后处理旧零值；未区分来源的目录默认重量不能当成已做实绩。 | 明确计划目标 > 本人最近有效且口径一致的训练 > 经验证的目录建议；未知是 null，合法 0 不丢弃。只写实际录入值或由用户明确确认的预填值。校验输入、状态、边界及撤销；先验证再变更。完成/跳过/待完成独立表示；完成后编辑需撤销；新增永远待完成。对 coach_post_session 的业务规则单独回归，避免修改教练语音工作流。 |
| P0-3 权限与结束 | `assertSessionEditor` 只检查学生或教练归属；学员名下未发布的教练课后表在 GET 隐藏，但通用写端缺同等会话类型约束。结束接口按账号是否拥有教练权限选角色，双角色学员可能跳过零完成组限制。服务层的 `finalizeKeys` 也未绑定会话，命中后直接返回所映射记录。 | 把「学生本人执行会话」和「教练编辑并发布本人课后表」拆开校验；幂等键按会话和操作归属隔离，返回前再次确认会话与权限；旧数据按同一会话兼容读，不跨记录复用。验收：双角色学员零完成组仍不能结束；跨账号及跨会话键不返回他人报告；未发布课后表不可从学员端写入；合法重试不重复奖励；过期回包不能写到切换后的账号。 |
| P0-4 批量新增和恢复 | 一次确认实际上连续 POST。失败只报告确认数量；响应丢失时不知道哪一项已创建，重试整批可能重复。 | 保留每项确认结果和重试标识；重试前以服务端记录核对，避免同请求重复创建；保留用户有意重复添加动作的能力。再分别验证中途断网、后端已写但回包丢失，以及返回草稿列表后可恢复。 |

### 实施顺序与发布门槛

- 路由边界：`训练首页 → 新建训练（自由或计划）→ 训练执行 ↔ 动作选择 → 结束确认 → 只读报告`；`进展 → 月历当天列表 → 同一只读报告`。先保留现有页面和 API 入口；完成 P0 后才调整入口、层级和样式。
- 保存状态：原始输入 → 本机草稿 → 失焦入队 → 服务器确认（仅清理这次提交的字段版本）或失败保留 → 同字段可继续输入或重试。完成组必须收到服务端确认；结束先检查未保存组，再按真实结果转入报告。跨账号、跨会话及过期响应不得驱动 UI。
- P1 再调整 01–15 的高频交互及报告/计划入口。P2 再细化月历、趋势、主题及小屏排版。动作库、报告与日记沿用现有数据，不引入原型演示数字。
- 本轮在隔离测试环境复跑 6 个相关测试文件，47 项通过。它们没有覆盖所有上述缺口；现有 6 项全量失败仍按 V1.26 基线记录，本轮未复跑全量。未运行微信编译、实机或弱网验收，因为本轮无业务改动。后续逐项验证 320/375/430px、深浅主题、iOS/Android 键盘、弱网及切后台。
