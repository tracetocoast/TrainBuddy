用内存会话复现了缺失重量的两个结果。发 `weight: 0` 后杠铃卧推首组为 `0`，`loadBasis=total`。仅把请求改成 `weight: null` 又会命中内置预设 `50 kg`。两组都仍是 `pending`。因此 P0 需要明确区分缺失、显式空值、已知零值和计划预填。旧历史中无法判定来源的零值保留原记录，不作为可信的预填依据。

## 3. 新旧操作流程对照

|场景|现状|拟改流程|
|---|---|---|
|自由训练|训练 → 新建训练 → 自行添加 → 第二个训练页 → 动作库 → 确认 → 轮盘开始动作|训练 → 开始训练 → 选择动作 → 一次添加 → 原训练页自动展开第一项。保留 `new-workout` 直达和模板入口作为兼容路径|
|未完成训练|进入训练页时通常自动恢复，浏览计划路径可绕开自动恢复|训练首页主按钮显示「继续上次训练」。恢复同一个 session 和草稿。存在多条历史草稿时明确选中哪条。需要新建时先按现有规则继续、完成或放弃旧草稿|
|切换动作|回轮盘 → 定位 B → 开始动作|在当前页点 B 一次。A 的草稿和保存反馈仍在各自行中|
|录入与完成|在当前行输入 → 暂存 → 点完成写入|输入 → 键盘确认或失焦后排队保存 → 本组完成 → API 确认后变绿。撤销完成保留参数|
|历史|进展月历点日期查看混合摘要，训练报告另从训练页进入|进展 → 月历 → 日期 → 同一天独立会话列表 → 已授权训练报告。切换身体/饮食保留当前日期|

点击和跳转为源码路径推导，实际耗时和手势待工具与真机验证。

## 4. 信息架构与 5. 执行页详细设计

```text
首页      课程、教练协作入口
训练      继续上次训练 / 开始训练 → 本页执行
          最近教练报告 → 只读详情
          待练计划、动作库
进展      月历 → 训练 | 身体 | 饮食
          当日记录 → 报告 / 身体历史 / 日记
```

- 执行页顶部保留会话标题、添加动作和结束训练。动作行以分割线区分，显示小缩略图、名称、完成数/总组数和展开符。只展开一个动作，点击标题切换。恢复时优先用仍有效的上次动作 ID，再选首个未完成项。无动作显示一个添加入口。当前动作全部完成后保留可见，下一动作由用户选择。
- 展开区显示可信肌群、最近一次参考日期、重量说明和四列表格「组｜重量｜次数｜完成」。行首显示组号或橙红「热」，点击展开行内短菜单，可设热身/正式或选择删除。删除先确认，服务端拒绝删除最后一组时保留原行。新增组排在该动作末尾，并在 API 确认后出现。动作历史及详情放在组表下，图片保持缩略尺寸。
- 数值单元格用原生数字键盘。缺失显示「—」，已确认的零值仍显示 0。重量口径优先用会话明确字段，其次用经过核验的动作 ID 映射。设备类型不足以区分双哑铃和每侧训练时，显示通用说明，不自行转换参数。
- 训练控制器保留一个服务端快照，按账号/角色/session/组/字段保存原始输入与编辑版本。失焦与键盘确认合并进单条串行写队列。每次提交取快照，成功后只清理本次确已保存且版本未变化的字段。迟到响应须同时匹配身份、会话和代际。完成、撤销、类型、增删和结束与数值提交串行，完成时读取当前最新有效值。相同操作在途防重。失败显示对应行「未同步」和重试入口，保留输入。跨设备写入仍以现有服务器规则为准。
- 休息计时在列表下方使用紧凑提示，允许关闭和提前结束。优先使用有明确字段的计划设置，否则使用当前账号最近选择。提供关闭、60/90/120 秒及自定义。以截止时间减当前时间计算，后台回来重算。减少动态效果只影响反馈和动画。首版使用静态到期提示，震动遵守现有减少动效设置。
- 复用亮暗主题 token，用细分割线和等宽数字。完成行浅绿底加勾，热身用橙红字，状态不只靠颜色。完成列保留 44px 触控尺寸，数字列随屏幕宽度伸缩。键盘避让和底栏安全区在 320、375、430px 验收。

## 6. 动作排序与历史预填数据

从当前学员自己的 `listSessions(status=completed)` 构建索引。复用 `trainingReport.visible` 对报告状态和发布范围的判断，再按 session ID 去重，只纳入至少有一组 `done` 的动作。按 `exerciseId` 匹配完整动作库 ID。旧数据缺 ID 时，只允许在可信别名/名称唯一匹配目录后回补展示关联。重名不跨动作合并。每个动作在同一 session 只加一次。次数相同按 `ended_at`、业务日期和稳定 ID 排序。缓存按身份隔离，完成训练后刷新。

新建自由训练时，优先使用最近一次有效完成训练的逐组快照。只拷贝可信实际值和确认组类型，跳过未做或缺少有效数据的组。新组重新生成 ID，状态统一为 `pending`。复制计重口径时要求来源一致。已发布计划以计划快照为准。无个人历史时按动作库可信组数和次数初始化，完整目录未带可信训练预设时使用经产品确认的可编辑默认值。保加利亚分腿蹲的验收使用 3 组作为拟定起点，未知重量留空。

动作库增加常用和最近的快捷区，继续使用同一个搜索、器械/肌群筛选和选择状态。收藏入口取决于现有是否有持久化数据，当前已核对路径尚未发现可复用的训练收藏。按已选 ID 暂存确认结果。多选先复用现有逐个创建，准确显示已添加与待处理项。未知响应先重新读取当前 session 核对。对严格的三项原子添加另列接口提案。

## 7. 训练日历的数据来源

|区域|数据与规则|
|---|---|
|月视图|复用 `growthApi.monthRange`、日期工具和 `growth.buildCalendar`。默认上海时区当月。左/右月切换与点选日期。今天有轻边框，选中态高亮。一个日期最多一枚可用训练部位短标签，同日多次用次数提示，详细列表放月历下|
|训练|从已授权 `listSessions` 取数据，按业务日期归组、按结束时间排序、按 session ID 去重。一天内多个 session 分开呈现。月历训练标记与详情使用同一可见过滤，避免把日记投影或 marker 中未共享会话的提示当正式报告。详情重新 GET 并复用只读报告校验|
|标题与肌群|用户自定义标题 → 已发布教练主题 → 完成动作可靠主肌群的前 1–2 项 →「力量训练」或「本次训练」。现有数据未独立标记标题来源，明确非通用标题原样显示，`自主训练` 等已知系统通用标题才允许替换。按完成组数和不同动作覆盖选择代表肌群，排除辅助和不可靠映射，不写回历史标题|
|容量|只对已完成、已记录重量及次数、计重口径明确且可比较的组计算。杠铃总重、每只哑铃、机器配重、自重加负和每侧次数须先有可验证口径。首版缺乏依据时省略容量。未知不能计作零或混算|
|身体|复用 `bodyMeasurementApi.list()`，按记录日期查询 `values`，指标名和单位用 `METRICS`。缺失显示「未记录」，同一天多条数据保留时间和记录 ID，可进入 `body-history`|
|饮食|复用 `/calendar/markers` 的饮食标记和 `diaryApi.getDailyView(app, studentId, date)` 的餐次、已记录营养和饮水，使用原日记作为完整编辑入口。权限沿用现有学员身份和分享机制|
|请求隔离|用账号、月份和选中日期校验旧响应。训练、身体和饮食独立加载、重试与清空，切分类保留月份/日期。身体或饮食请求失败显示失败状态，不能伪装空数据。缓存不跨账号或角色|

当前 `listSessions` 与 `bodyMeasurementApi.list()` 无月范围参数。首轮增强在当前账号授权结果上分月索引，避免每次切分类重复全量拉取。数据量达到性能瓶颈后再评估区间查询，先记录请求数量和响应体积。

## 10. 后端协议影响与提案

- **P0 现有新增动作路径。** `POST /sessions/:id/exercises` 在自由训练中区分未提供重量、显式 `null` 与合法数值 `0`。建议由新前端显式传 `weight: null` 表示未记录。服务端在 `sourceType=manual` 按字段存在性保留 `null`，计重口径用 `unknown` 直到有可信元数据。计划与教练旧调用继续沿用既有默认值。响应沿用 `Session.exercises[].sets[]`。测试确认同一请求的未知重量、用户明确输入零和计划已知重量分别保持语义。
- **P0 组 PATCH。** 现有 `PATCH /sessions/:id/sets/:setId` 的 `actualWeight: null` 表示不修改，暂不将其改为全局清空。空白输入先留草稿，完成前提示校验。建议支持按实际字段验证 `done`，兼容旧客户端和教练路径。前端先用同一队列和现有 PATCH 防止错序，`finalize` 继续使用现有 revision/幂等校验。
- **P1 组配置与多选。** 单动作 POST 可先作为兼容路径。若要一次事务添加三项及复制不同组，提议同一路由支持额外 `exercises[]` 形式或专用批量入口，字段为 `exerciseId`、可空的逐组重量/次数、`setType`、可信 `loadBasis`。服务器重建组 ID、统一 `pending`、校验 1–30 组和动作权限，并按操作键幂等。若仅使用现有端点，串行添加及后续 PATCH 为分步写入，失败必须能识别已生效项。
- **P1 新组类型。** 现有新增组后可用 PATCH 设置类型，返回两步结果。若要求创建时原子继承，建议新增组请求接受可选 `setType`，旧客户端不传时沿用当前规则，非法枚举返回校验错误。目录 ID 校验与保存可利用现有 `exerciseService`，历史旧行无需迁移。
- **P2 数据读取。** 月历首期复用已有接口。需要范围分页时提案 `GET /sessions?from=YYYY-MM-DD&to=YYYY-MM-DD&cursor=...` 为可选字段，保持所有权与发布过滤。后端改动限上述训练数据边界。
